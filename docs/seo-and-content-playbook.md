# SEO 与内容执行手册（study.791860.xyz）

> 本文件是 2026-10-31 优化时把笔记里的方法落成仓库规范的记录。
> 代码真源仍是 `src/utils/seo.js`（head 单一真源）、`src/ssg/sitemap.js`（真实 lastmod）、
> `scripts/verify-routes.mjs`（全量断言）；本文件不替代它们，只规定“新内容上线前按什么标准做”。

## 1. Keyword-to-Page：一个页面 = 一个意图簇

- 新课、新题、新聚合页上线前，先写一句话：这个页面承接哪个搜索意图、对应哪个关键词簇。
- 一个簇只由一个主页面承接，不要为同一个意图建两个近重复页面；近重复页先合并，再谈新页。
- URL 结构就是书的目录：课程 / 分类 / 题目三级语义化 URL 不随意改；改 URL 必须同时补 301（见 `_redirects` 生成逻辑），不要产生孤儿旧地址。
- title / description 写给人看，自然带出核心词，不堆关键词；description 只讲内容是什么，不写界面功能。

## 2. 内链：现有环形轮转 + 每季度外部校验

- 现状已固化：题目页“标签重合度优先 + 环形偏移轮转”、课程封面与题库分类双向互链、构建期零死链断言。
- 每季度用一次外部内链分析工具（例如笔记里的 Jev 内链工具：输入 URL 自动做全站抓取、链接建议、锚文本生成与结构可视化）对照自查，找盲区；不替换现有环形逻辑。
- 新页面上线必须同时满足：能从至少一个分类/课程页点到、能回到分类/课程页、构建校验的死链断言通过。

## 3. GEO：先测再建，按缺口回补

- 顺序固定：定位 → 主题与信源 → 品牌信任；先测 AI 实际引用哪些信源（Reddit、知乎、行业媒体还是本站），再建设，再复测。
- 本站适合 GEO 的资产是体系化教程 + 带可运行代码的题库，先把首页、核心功能页、解决方案页、使用场景页的定位写清楚，再谈“被 AI 引用”。
- 不保证获得推荐：任何 GEO 改动都不写“保证收录/保证被引用”这类承诺；效果以 Search Console 与 AI 引用实测为准。
- GEO 分析工具（例如 2026-10-27 增量里的 GEOInflow）部署前先确认它是分析工具还是又一个清单，避免重复造工具清单。

## 4. 技术审计清单（每次大改后跑一遍）

- sitemap：单文件 + sitemap-index 双入口、每条 URL 都有合法 `YYYY-MM-DD` lastmod、sitemap 与磁盘静态页双向零差集。
- head：每页 title / description / keywords / robots / canonical 与 `seoForRoute` 算出的一致、标题与描述全站唯一。
- 结构化数据：Course / Article / QAPage / ItemList / BreadcrumbList 按页类型齐全，不给错误页写 canonical。
- 爬取规则：`/progress/` 保持可抓取 + noindex，不要用 robots.txt Disallow 挡掉 noindex；未知路径返回真实 404，不要全量 SPA 回退。
- 工具链边界：Claude SEO 的脚本层在本机 VM 上会被 SSRF 守卫挡掉请求（这是守卫设计，不是 bug）；剧本层（technical / drift / sitemap / google 四份 checklist）可直接用，工具层要放在出口直连的机器上跑。GSC / PageSpeed / CrUX 这类真数据源需要站长授权后才能接，不要擅自用他人账号。

## 5. 任务页规范（HIX.AI 任务页拆分，落到题库升级）

- 目标形态：一个 Query、一个任务、一个真正能用的页面、一个下一步行动。
- 题库从“条目”升级成“任务页”时，每页至少要有：明确的任务陈述、可运行的代码示例、步骤、限制说明、FAQ 或下一步行动；只加字数不加“能用性”的不算升级。
- 示例、步骤、限制、隐私说明、FAQ 的优先级高于多写两千字；页面本身必须能用，不能只有文字。
- 本次优化只定了规范，没有批量改写 304 道题；批量升级要按分类分批做，每批上线前跑 `npm run check`。
